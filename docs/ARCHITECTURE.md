# 架构说明

## 数据流

```mermaid
flowchart LR
    P[TDX / AKShare / Baostock] --> F[数据适配与增量更新]
    F --> D[(SQLite)]
    D --> M[大盘与板块评分]
    D --> X[共享个股因子]
    C[行业 / 概念 / 涨停池] --> X
    X --> S[策略家族信号]
    M --> R[总分与风险扣分]
    S --> R
    R --> E[Excel]
    R --> J[静态 JSON]
    J --> W[本地面板]
    J --> G[GitHub Pages]
    R --> H[入选历史与未来收益]
```

## 每日任务

`src/run_daily.py` 负责以下顺序：

1. 获取项目级单实例锁，载入 YAML 配置并初始化数据库表
2. 自动任务探测交易日状态，执行历史补全或每日增量更新
3. 校验目标日期股票覆盖和三大指数完整性；不满足时失败关闭，不回退发布旧报告
4. 构建股票池和风险过滤名单
5. 计算市场、板块、股性、量价和 RPS 因子
6. 一次性构建共享策略特征
7. 运行启用策略并按家族去重
8. 计算风险扣分和总分排名
9. 为 Top N 补充细分行业、概念、涨停线索和行业阶段表现
10. 在最终排名之外运行安全自定义公式，生成独立命中集合
11. 保存 Top N 历史并回填未来收益
12. 生成 Excel、JSON 和静态网页
13. 写入任务状态

工作日午间触发时，流程会强制刷新当日尚未收盘的日 K，并生成标记为 `intraday` 的临时快照；该快照不保存正式入选历史，也不回填未来收益。盘后触发会再次刷新同一交易日，原子替换正式 Top N 快照。

自动任务在周末或由三大指数查询确认休市时记录为 `skipped`。行情源不可用属于未知状态，任务仍会尝试更新，但必须通过目标日期覆盖校验才允许生成报告。显式 `--date`（包括离线重算）同样要求该日期已有完整行情，防止未来日期、休市日或缺失日期被旧数据冒充。面板、计划任务和手动命令共用同一项目级锁，不能并发写入数据库或报告。

## 数据提供者

默认 `tdx`：

- 不需要用户名或密码
- 支持主机故障转移
- 支持分块并行初始化
- 支持断点续跑和增量更新
- 系统性失败时使用熔断，避免无限重试

`akshare`、`baostock` 和 `mixed` 仍可配置，但不作为默认生产路径。

## 候选股背景信息

`src/stock_context.py` 只为排名靠前的候选股补充背景，不参与基础行情更新，也不会因网络失败中断报告：

- `stock_context` 缓存东方财富 F10 的一级行业、细分行业和核心概念
- `stock_event` 保存报告日涨停池事实，仅将概念关联描述为“线索”，不冒充新闻涨停原因
- `sector_context` 使用申万一级行业指数，保存 5 / 20 / 120 日表现和近 20 日异动次数
- 长说明进入 Excel 和个股详情抽屉，观察名单表格只使用短标签

缓存规模由 `features.context_top_n` 和 `context_cache_days` 控制。

## 策略因子缓存

`build_strategy_features` 对每个报告日期统一计算均线、阶段高低点、收益、波动率、量比、突破状态和距离均线等字段。策略只能消费共享结果，不应各自重复滚动计算。

同一家族的多个策略可能描述相近市场行为，因此总策略原始分为：

```text
策略分 = 各家族命中策略的最高分之和，最高 100
```

## 报告契约

`build_report_payload` 输出带 `schema_version` 的 JSON，包含：

- `market`
- `health`
- `strong_sectors`
- `top50`
- `top10`
- `strategy_performance`
- `strategy_distribution`

本地面板先读取 `/api/latest`；GitHub Pages 使用 `site/data/latest.json`，两者共享前端。

## 部署边界

- 本机：`start.bat` + FastAPI / Uvicorn
- 自动任务：Windows Task Scheduler 调用 `scripts/bootstrap.py`
- 容器：Docker Compose 挂载配置、数据库、报告、日志和站点
- 手机只读：本地任务生成 `site/`，GitHub Actions 只负责部署
- 服务器：Docker 面板置于带 HTTPS 和身份验证的反向代理之后

数据库不进入 GitHub，也不由 GitHub Actions 每日重建。

自动发布脚本只允许在目标分支本身执行，并要求本地与远端具备明确的快进关系。它只提交最新报告、历史索引、当日报告和历史保留策略产生的删除，不扫描 `site/` 下的其他脏文件。影响报告的源码、配置、脚本、网页模板或依赖有未提交修改时，发布直接停止。发布提交带有固定标记并按已校验的精确提交 SHA 推送；推送失败时提交保留在本地，后续运行只会在再次校验提交内容后重试。网页模板与静态资源变更必须通过正常 PR 进入目标分支。

通过 `scripts/bootstrap.py` 执行每日任务时，同一把项目锁会从数据更新前持续持有到可选的 Pages 发布完成；子进程只能使用父进程传入且与锁文件匹配的随机令牌复用锁。直接调用 `run_daily.py` 或 `publish_pages.py` 时仍会自行抢锁，因此生成和发布不会被另一条手动或计划任务穿插。
